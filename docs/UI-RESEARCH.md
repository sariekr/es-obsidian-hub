# Icons and colors for ES Obsidian Hub

Checked on **25 October 2026**. The official Community pages were read through Bright Data, supplemented by official maintainer documentation and GitHub API reads of tagged release manifests. Web search/page tools were used for compatibility issues and documentation. Release and development-branch requirements are recorded separately below. No candidate plugin was installed or tested in the demo.

## Decision and implemented scope

Source **1.3.0** uses Obsidian's built-in Lucide icons and the existing AnuPpuccin variables. This solves the custom card problem without a new plugin, downloaded icon pack or theme replacement. Folder names have no implied meaning: **Customize → Type icons** lists live Hub folders and lets the user choose from twelve icons. All unconfigured Types use a neutral folder. Text labels remain visible on cards and in the Type picker. Preferences are keyed by folder name; a renamed folder needs a new choice. Icon choices do not move or edit notes.

The disconnected demo has explicit choices: Learning → graduation cap, Personal → person, Quick Notes → sticky note, Work → briefcase, YouTrack → ticket. These are demo preferences, not bundled defaults. Any other direct Hub folder can use the same chooser.

Priority uses shape plus text: Urgent → circled alert, High → double chevron up, Medium → equals, Low → chevron down. Only High and Urgent have small theme-derived color accents. Type/action icons remain neutral, selection/focus uses the theme accent, and the vendor's three column colors remain unchanged. Done cards retain a struck-through title with fully readable controls. Calendar/Mail, YouTrack, Slack, Customize, Search and Preview receive consistent small icons; their order and labels stay intact.

A fixture-only neutral variant was compared with the restrained priority accents in both light and dark appearances. The restrained variant was selected because it adds an urgency cue without assigning another color system to Types or whole cards. Card text increased from 11px to 12px and controls from 25px to 28px. Narrow cards wrap controls and retain full accessible labels/tooltips when visible text truncates. No Type color picker or broader sidebar redesign was added.

## Integration and compatibility findings

[AnuPpuccin v1.5.0 documentation](https://github.com/AnubisNekhet/AnuPpuccin/blob/v1.5.0/README.md) supports Style Settings and the existing light/dark palette. Its rainbow folders follow filesystem order, so they are unsuitable as a stable semantic Type map. The bundled theme and vendor plugin remain unmodified.

[Style Settings documentation](https://github.com/community-archive/obsidian-style-settings) describes declared CSS settings, `variable-themed-color` and the `parse-style-settings` event for plugin-defined CSS. It exposes declarations rather than inventing Hub controls. Historical [issue #147](https://github.com/community-archive/obsidian-style-settings/issues/147) reported missing AnuPpuccin settings on Obsidian 1.5.8/Ubuntu; it is not evidence that our Mac runtime is incompatible. A useful optional demo would pin **1.0.9**, change only AnuPpuccin's palette/accent through its settings UI, and compare native light/dark rendering and restart persistence. No Hub-specific declaration is needed unless we decide to expose additional CSS controls.

[Iconic's documentation](https://github.com/gfxholo/iconic) lists files/folders, tabs, bookmarks, tags, properties and the ribbon. Those surfaces do not establish support for our `.obk-card` DOM. The built-in implementation explicitly decorates our card controls and Type picker. Upstream [property API fix #268](https://github.com/gfxholo/iconic/pull/268) illustrates why matching the app version matters. A later Iconic trial should demonstrate explorer/tab/property icons on a compatible pinned version and check our property picker independently. Code is MIT-0; third-party resources have separate licenses, so bundling would still require review.

Notebook Navigator's [known issues](https://github.com/johansan/notebook-navigator/issues/363) identify window-border artifacts with **AnuPpuccin Cards workspace plus Obsidian transparency**, linking issue #210. This is a specific combination, not a blanket theme incompatibility. [Issue #1498](https://github.com/johansan/notebook-navigator/issues/1498), concerning a Base used as a folder note opening twice, is listed as fixed in **3.4.3**; it does not prove our custom board integration. Any future trial should use the tagged release, check board opening/leaf behavior, and assess the larger sidebar change. Its license is GPL-3.0.

## What was actually tested

Native Obsidian 1.11.7 in the independent `.local/demo-vault` displayed the real selected Lucide glyphs, widget/action icons, priority symbols and Done treatment. Mouse and keyboard icon selection, default reset, Type picker, combined board filters, Preview/Escape and disconnected Calendar/Mail switching were exercised. Light/dark views and a roughly 750px content area were visually inspected. The 13 original demo notes remained byte-identical; a temporary Done/Urgent QA note was removed afterward. The personal vault was not changed.

The synthetic browser fixture separately tested settings failures, reload persistence, arbitrary/long folder names, cleanup and sampled contrast. Its mocked `setIcon` uses a placeholder SVG, so native inspection supplies the actual glyph evidence. Sampled light text/icons reached at least **5.97:1 / 3.51:1**, dark **9.36:1 / 6.74:1** with the chosen scheme. These are fixture measurements for the checked surfaces, not a full-app accessibility certification or measurements of every native theme combination. See [Verification](VERIFICATION.md) for commands and limits.

Remaining decisions: whether whole-theme palette controls justify an optional Style Settings demo, whether native navigation needs Iconic or Notebook Navigator, and whether to publish a new release after the PR review. None of those plugins is bundled, enabled or claimed compatible from this research alone.


## Widget list proposal — 25 October 2026

The official Community pages and developer images were inspected through Bright Data and computer use during the widget-refresh work. These are visual references, not tested plugin integrations:

| Reference | Observed pattern | Proposed use in Hub |
| --- | --- | --- |
| [Notebook Navigator](https://community.obsidian.md/plugins/notebook-navigator), [developer repository](https://github.com/johansan/notebook-navigator) | Date-grouped note list, stronger titles, excerpts and secondary timestamps; restrained selected rows. | Group Mail/Slack into Today, Yesterday and older dates. Keep sender/title first, subject/message second, account/channel last. Preserve chronological order within each date. |
| [Day Planner](https://community.obsidian.md/plugins/obsidian-day-planner), [developer image](https://raw.githubusercontent.com/ivan-lednev/obsidian-day-planner/HEAD/assets/hero-daily.png) | Aligned hours and separate event content. | A simple Agenda time column; no drag-to-reschedule or full timeline editor. |
| [Calendar](https://community.obsidian.md/plugins/calendar), [developer image](https://raw.githubusercontent.com/liamcain/obsidian-calendar-plugin/master/images/screenshot-full.png) | Quiet month navigation and small day markers. | Keep the existing month grid; its meeting indicators must not inherit the reference plugin's daily-note word-count meaning. |

Open [the standalone interactive HTML proposal](prototypes/widget-lists.html) in a browser. It has fictional Mail/Slack/YouTrack data, light/dark appearance, comfortable/compact density, an 800px panel mode, Mail filters and empty state, Slack filters, Calendar Agenda/Month, simulated Refresh all, and a page-only Scratchpad. Reload clears the demonstration. It makes no network requests or vault changes; external source links open only when clicked. It runs directly as a local file without npm or a server.

The proposal inherits the AnuPpuccin palette family, system UI font and existing three-widget/three-column arrangement. It keeps Type text labels and uses no personal folder-name rules. YouTrack groups by State because these are issue records, not messages with a comparable received date. Only Mail has an unread cue; Slack's adapter does not provide unread counts. Priority stays separate from selection and State. Row actions remain explicit source-open actions, demonstrated with explanatory feedback instead of opening real accounts.

**Implemented in runtime 1.4.0:** one Refresh all widgets button, Hide/Show inside Customize, per-source freshness labels, Calendar/Mail 10m and YouTrack 6h visible-view reads; Slack remains 5m. **Proposal only:** grouped lists, revised row spacing/type hierarchy, YouTrack State groups, Agenda time alignment and a density setting. No Notebook Navigator code, images or plugin dependency was copied or installed. Installing it would not automatically style our custom widget DOM.

Browser interaction and visual checks covered desktop dark, 800px light/compact and a 480px viewport with horizontal widget/board scrolling. Mail Unread returned two synthetic rows; Personal + Unread showed the empty state; DMs returned two rows. Calendar month selection and refresh busy/completion states worked. Sampled normal text/context/date/time colors against the prototype base reached at least 7.36:1 dark and 5.14:1 light. This is limited prototype sampling, not a full accessibility certification or a native-runtime contrast measurement. One prototype icon/button ID collision was corrected during this pass.

Recommended next implementation, if selected: start with Mail/Slack date groups and shared row spacing, preserve each adapter's sorting, row limit, safe text rendering and source-open behavior, and restore per-tab scroll/filter state after redraw. Then evaluate State grouping and Agenda separately. Reuse built-in icons/theme variables; no additional plugin is needed for these widget changes. A separate Notebook Navigator sidebar trial still requires the pinned release and compatibility checks described above.
